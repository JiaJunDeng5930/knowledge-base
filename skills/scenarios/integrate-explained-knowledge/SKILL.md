# 将材料讲解的知识整合进知识库

读取或维护数据库前，先完整读取[知识库通用 skill](../../knowledge-base/SKILL.md)。子弹笔记、引用、标签和数据库访问遵循该 skill 与其按需资料。

不要查证用户提供内容的事实正确性。

## 形成知识模型

在提出数据库变更前，读取足以确定父路径和合并既有内容的知识库上下文。

将教程中的知识整理成知识模型，使用子弹笔记的结构来组织

并且注意几个点：

* 同一个知识只写一次，不要有双源。
* 按照知识本身的结构来组织知识模型，而不是按照教程中讲解的结构来组织知识模型
* 描述一般规则时使用抽象形式。如果知识有对应的抽象语法就是用抽象语法，例如数学的数学定义，语法的抽象描述等
* 结果应当是知识模型而不是知识模型的讲解
* ”教程中的知识“既包括教程中明确被主题化的，也包括能够看出来但是没有被主题化的

## 确认后写入

向用户呈现变更时，使用父路径 + 子弹笔记的格式。

用户提出修改时，修改知识模型并重新展示。用户确认以前，不得向数据库写入。

用户确认后，才通过已授权的数据库接口写入。如果实际写入必须改变已经确认的知识模型，先更新知识模型并重新取得确认。

修改本 skill 时，先读取 [DECISIONS.md](DECISIONS.md) 中的用户决策。
