# 将材料讲解的知识整合进知识库

本 skill 处理用户指定材料中实际传达或讲解的知识。材料的文体和说话者身份不决定内容是否进入知识模型。

读取或维护数据库前，先完整读取[知识库通用 skill](../../knowledge-base/SKILL.md)。知识记录、树结构、引用、标签和数据库访问均遵循该 skill 与其按需资料；本 skill 只规定材料知识的选择、整合和提交前确认。

## 材料边界

用户指定的整份材料是本次输入。材料可以是连续教程、教程与后续问答的组合、完整的对话问答，或其他讲解形式。只有用户明确纳入本次任务的内容才属于材料；材料以外的既往对话、外部资料和模型背景知识不属于本次输入。

默认不把原始材料写入数据库。用户明确要求保存时，按知识库通用 skill 和当次要求安排保存，并把相关写入列入提交前的拟议变更。保存原始材料不能代替把其中讲解的知识整合进 `knowledge` 树。

## 选择材料中的知识

纳入材料实际讲解或明确传达的全部知识。主线内容、细节、补充说明和易错点使用同一判断标准；篇幅和位置不构成省略理由。

材料直接断言的内容即使没有理由、证明或后续展开，也属于材料传达的知识。例如，材料只写“`field1` 是必需字段”时，仍纳入该约束。

具体案例可以形成材料直接支持的最小一般化。例如，材料解释某次失败源于缺少 `field1` 时，可以形成“`field1` 是必需字段”；不能继续补充材料没有讨论的其他输入约束。

保留知识成立的条件、适用范围和不确定性。不得把“可能”“通常”或有条件成立的内容改写为无条件结论。

材料讲解错误认识、常见失误或反例时，保留错误内容、后果和纠正内容之间的关系，不能只留下纠正后的结论。

推导过程表达了知识关系时保留相关推导。案例用于讲解一般知识时，只保留案例承载的知识，不自动保留偶然的名称、数值或其他填充内容；案例本身是讲解对象时，保留与该对象有关的内容。

合并材料中围绕同一对象分散或重复展开的讲解。合并不得丢失各处分别给出的条件、细节、理由或易错点。

当材料无法说明某项内容是讲解对象还是顺带使用的信息时，把该内容纳入拟议知识模型，让用户在提交前确认阶段决定是否保留。

## 限制材料能够支持的结论

材料只使用某项背景知识而没有讲解该知识时，不把该背景知识作为本次材料产生的新知识。可以读取知识库中的既有背景知识来理解材料和确定位置。

不得对材料进行演绎闭包。可以合并围绕同一知识对象展开的分散说明，不能仅因不同说明能够共同推出新关系，就把该关系写成材料讲解的知识。例如，材料分别讲解“`fun1` 的输出总是只读对象”和“只读对象不能传给 `fun2`”，却没有讨论两者的组合时，不得新增“`fun1` 的输出不能传给 `fun2`”。

页面导航、讲解预告、进度提示和纯粹的行文过渡不进入知识模型；相关内容本身是材料讲解对象时，再按普通知识处理。

## 不检查材料的事实正确性

不为候选知识执行外部搜索或资料核验，也不使用模型背景知识判断材料是否正确。模型认为某项内容可疑，不构成启动查证的理由。

为了完成整合，仍须读取相关的既有知识。读取时如果直接发现材料内容与既有知识无法共存，并且无法确定应采用哪项内容，向用户说明具体冲突并等待选择。该询问只解决实际写入冲突，不扩展为事实核验。

## 形成拟议知识模型

在提出数据库变更前，完成材料知识的选择，并读取足以完成合并和组织的既有知识。

既有知识已经完整表达材料所讲内容时，不重复写入。材料增加了条件、细节、推导或易错点时，把新增内容整合到相应位置。合并时保留既有记录中材料没有涉及的知识。

材料顺序只帮助理解讲解关系，不决定知识树的最终结构。按照知识内容、知识库通用 skill 和当前数据结构确定位置。可以按组织需要创建或修改记录、合并重复记录、移动节点、调整子树与兄弟顺序，以及建立记录级引用；结构调整不受本场景划定的局部范围限制。

为组织内容而创建的标题或父节点是普通知识记录，不需要本场景专用标记或单独审批。整个知识库的结构都按通用数据结构维护。

新形成的知识正文主要使用中文。其他语言的材料整理为中文；代码、数据库标识符、程序标识符和需要保留原文的标准术语保持必要的原始形式。语言转换不得改变条件、知识关系或不确定性，也不得补入材料没有讲解的知识。

## 确认后写入

先向用户展示完整的拟议变更。展示内容必须包括准备新增或修改的知识正文、相应的树中位置，以及节点移动、顺序调整、引用和原始材料保存等拟议结构变更。用户最初要求处理或保存材料，不能代替拟议模型形成后的确认。

用户提出修改时，先修改拟议知识模型并重新展示。用户确认以前，不得向数据库写入候选记录、临时组织节点、结构调整或确认界面内容。

用户明确确认最终拟议模型后，才通过已授权的数据库接口提交获准的正文和结构变更。正文、组织节点和其他结构调整共用这次最终确认，不分别增加审批。如果实际写入必须改变已确认的内容或结构，先更新拟议模型并重新取得确认。

修改本 skill 时，先读取 [DECISIONS.md](DECISIONS.md) 中的用户决策。
