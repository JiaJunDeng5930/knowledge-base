# 每日知识复习

调用后直接读取今天截至当前时刻已到期的 FSRS 对象，呈现第一项复习。不要先询问是否开始、要求用户提供 cue、选择评分方式或手动调用其他 skill。用户可以指定主题、数量或时长；没有指定时复习全部当前到期内容，直到完成或用户结束。

本 skill 完整规定复习所需的概念与交互。按 [数据接入与保存](references/data-access.md) 自动取得共用数据模块，完成数据库读写与 FSRS 计算。复习问题临时生成，不作为核心数据保存。

## 复习对象

| 概念 | 本场景中的含义 |
| --- | --- |
| 知识应用场景 | 一类知识进入的活动，例如实际制作、排查问题。活动决定已知信息、需要作出的判断及后续行动。 |
| 场景等价类 | 针对具体知识，在同一知识应用场景中，知识参与的处理和所需理解相同、其中一种情况的掌握可以推广到其他情况的一组使用情况。 |
| cue | 表示全局合并后的场景等价类。不同知识指向同一实际应用情形时合并为一个 cue，关联该情形需要的全部知识，共用一份 FSRS 状态。`fsrs.cue` 保存这一类情况及学习者需要恢复的具体理解。 |
| 触发条件 | 具体情形中使 cue 所描述的知识应用成为必要的条件，包括当前活动、目标、已有信息和观察到的现象。 |
| 关联知识 | 通过 `fsrs_bullet` 关联的全部 bullet 所提供的知识；bullet 是有序子弹笔记中的节点，必要上下文还需沿父子关系和引用读取。 |

每次围绕一个 cue 恢复处理具体实例所需的整体理解。可以用一个或几个问题完成考察。不要把每条 bullet、每个问题或同一 cue 的表面变化分别记录成独立复习对象。

## 自动开始与选择内容

1. 按数据接入说明连接已配置的知识库，查询 `due_at <= current_timestamp` 的对象，按到期时间、id 排序；包含逾期对象和已经到期的新对象。当天稍后才到期的对象暂不提前复习。
2. 用户指定主题时，先在知识库定位相关子树或内容，再筛选关联的 cue；只调用 skill 时使用全部范围。数量限制按完成评分的 cue 次数计算。
3. 读取当前 cue、全部关联知识和理解正文所需的上下文。确认知识应用场景、触发条件，以及本次必须考察的具体理解。只把关联知识中处理该 cue 所需的内容作为评分范围。
4. 取得可靠的题目素材后直接呈现第一项。不要在题目前展示 cue、关联知识正文、预期答案或会提示答案的主题说明。
5. 完成当前 cue 后重新查询到期内容。学习或重新学习步骤使同一 cue 再次到期时，可以再次呈现新实例；未到期时不立即重考。没有当前到期内容时结束，不等待未来时间或自行增加新 cue。

材料缺失、工具不可用、题目条件不足或正文被截断时，先尝试补全。仍无法可靠出题时，暂缓该 cue，保留其状态，继续其他可复习内容。全局数据库接入失败时说明具体缺少的能力，不编造题目或保存结果。

## 生成问题

从 cue 和关联知识确定需要考察的判断、原因、作用、概念名称或操作能力，再构造具体情形。所需层面由当前 cue 决定，不要求所有知识都统一回答名称、原因和作用。

- 在题目语义中包含触发条件。让用户处于一个有明确活动、目标和可用信息的具体情形中。
- 根据知识应用场景提问。实际操作场景询问现在应当怎么做；排查场景从已经出现的现象询问可能原因及判断依据。其他场景同样从活动本身确定疑问。
- 用一个或几个自然的问题覆盖所需理解；用户回答已经覆盖的内容不重复询问。需要用户回答的问题末尾使用 Unicode 上标数字编号。
- 不在问题、选项、前置说明、图片标题或替代文本中透露答案、命名待识别对象，或指定应调用哪项知识。提问“为什么”“有什么作用”可以要求解释，但不要把待解释的因果链预先写进题面。
- 呈现的信息形式对应实际应用中能取得的信息。需要观察外观时提供图片，需要观察变化时使用合适的动态材料，需要读程序时提供语言明确的实际代码。不要仅用“一段花括号代码”之类的概述代替可供检查的材料。为作出判断提供足够条件，避免额外引入关联知识以外的考点。
- 图片或其他素材必须实际可见，且经检查足以支持预期判断。按现有能力检索或生成素材，核对关键特征；涉及精确数据或结构时使用可核验的材料。不要以图片占位符代替素材，也不要通过描述结论补救无法取得的观察信息。
- 更换实例时，保持 cue 的场景等价类、所需理解和关联知识不变。

例如，一个 cue 要求在制作面包时根据面团状态判断是否继续揉制，关联知识说明揉制促进面筋形成、面筋网络保留发酵气体并支撑结构。可以呈现经过核对的面团图片，询问是否继续、为什么，以及所见结构的形成原因和作用。题面不提前写出“面筋网络”或“已经揉制充分”。

## 回答、补问与纠正

按回答的含义逐项判断所需理解是否已经体现，接受等义表达。区别没有表达、明确不知道和回答错误：

- **没有表达到某项所需内容：** 只针对缺少的部分中性补问，不提供答案线索，不把遗漏直接记作遗忘，也不要求重新回答已经说清楚的内容。
- **明确不知道或答错：** 直接给出正确内容和必要解释，说明错误涉及哪里；不要连续提示、诱导或要求猜到答案。完成本次评分与保存后，默认在同一回复中进入下一 cue。
- **已完整答对：** 简短反馈，完成评分与保存，然后直接进入下一 cue。

如果用户已经正确说明结构保留气体、提供支撑及形成原因，只缺少本次需要考察的名称，可以补问“这种结构的名字叫什么？”。名称补问成功后，结合整次表现评分；单凭发生补问不降分。

纠正后默认不要求复述，也不立即重复同一题。题目或素材自身有问题时撤回该题，修正后重新考察，不把题目缺陷计入用户评分。

## 用户追问与暂停

用户提出追问时暂停推进，先回答问题。追问与复习作答不同，不因用户要求进一步解释就判断为遗忘。

- 同一条消息同时包含作答和追问时，处理已有作答证据及所需纠正，再回答追问，保持暂停，不同时推出下一题。
- 回答追问后保持暂停，只有用户明确说“继续”或同义的恢复指令才恢复复习。不要把“明白了”“谢谢”当作继续。
- 如果下一题已经呈现但尚未作答，保留该题；恢复时继续这一题，不跳过，也不为它写入评分。
- 追问出现在评分前时，保留已经取得的作答证据。解释若透露了尚未考察的答案，不把随后复述当作独立回忆成功；已有证据不足以评分时，本次不评分、暂缓该 cue，恢复后继续其他 cue。
- 追问超出原 cue 要求的知识时，不因用户尚未掌握扩展内容降低原 cue 的评分。
- 按下一节把追问形成的新知识写入草稿。保存草稿不解除暂停，也不需要用户逐条确认。

## 追问产生的知识草稿

围绕追问检索现有正式知识，结合正文、上下文和引用判断是否已经包含相应知识；同时检查当前草稿，避免重复新增。知识库已有内容时正常解释，无须复制一份。

对于尚未包含、且能够明确表述的新知识，写入当前草稿的合适主题位置，必要时补充来源与引用。内容使用自包含的自然语言，保留适用条件；未经确定的推测不要写成确定事实。不要把整段聊天记录当作知识正文。

首次需要写草稿时，自动加载数据接入说明中的 bullet-review 模块。复用当前草稿，在已有拟议内容上增加或修改，保留其他待处理变更。实际保存成功后才视为已加入草稿。

复习期间只保存草稿，不提交正式 bullet，不自动创建或修改 cue 与 FSRS 关联。复习结束后提供草稿预览入口，让用户统一处理；结束复习不表示批准草稿。处理批注和提交整体 diff 继续遵守共用模块的用户确认规则。

## 自动评分

FSRS（Free Spaced Repetition Scheduler）根据带时间的评分更新记忆状态与下次到期时间。agent 按下面四档判断，用户无需选择评分按钮。评分含义依据 [Anki 官方评分说明](https://docs.ankiweb.net/studying.html#answer-buttons)。

| rating | 评分 | 判断依据 |
| --- | --- | --- |
| 1 | Again | 所需内容答错或无法回忆，需要纠正。只答对部分时，若缺少的内容使 cue 所需整体理解未恢复，同样使用 Again。 |
| 2 | Hard | 独立答对，但有明确的回忆困难或明显不确定。 |
| 3 | Good | 独立答对，需要正常回忆；正确回答的困难程度无法可靠区分时默认使用。 |
| 4 | Easy | 独立答对，且有充分依据判断回忆毫不费力。 |

中性补问用于补齐尚未表达的内容，不因发生补问自动降低评分。评分依据纠正或讲解前的独立作答证据；看到答案后的复述不提高本次评分。每个 cue 的一次完整考察只生成一个评分，多道问题不分别写日志。

不要根据消息间隔推断回忆耗时。只有确实测得主动复习用时，才记录毫秒单位的 `review_duration`；普通对话中使用 `null`。问题阅读、输入、离开对话和工具等待等无法分离时，不伪造用时。

## 保存与结束

按数据接入说明调用现有 FSRS 脚本计算，在同一条数据库语句中保存新状态和复习历史；不自行手算间隔，不改变 Scheduler 配置。只在确认保存成功后把该次复习计为已完成。

保存结果不确定时，核对同一对象、事件时间和评分对应的历史，再决定是否重试，防止把一次复习重复记录。保留未保存结果并说明失败；不要伪称已完成。

用户结束、达到其指定限制或没有当前到期内容时停止出题。未作答、仅跳过或证据不足的 cue 不更新状态。简短报告实际完成次数；有新增草稿时提供预览链接及涉及主题，供用户统一处理。存在暂缓内容时如实说明，不称全部完成。
